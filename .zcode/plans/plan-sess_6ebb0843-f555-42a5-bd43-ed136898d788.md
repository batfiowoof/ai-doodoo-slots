# Plinko: real physics + concurrent multi-drop

## Why this design (research-backed)
Casino plinko is always **server-decided outcome + client animation steered to match** — physics engines are non-deterministic, so a free-running sim can't be trusted to land where it paid. Our backend already returns the exact per-row L/R `path[]` from provably-fair RNG (`services/backend/internal/game/plinko/plinko.go`), and settlement is instant over HTTP — **no backend game-logic changes needed** ("what you watch is what paid" is preserved by construction).

For the animation, matter.js steering at `collisionStart` is the common approach but documented as visually janky, and it adds a ~25KB dep. Instead I'll build a small custom steered-physics module into the existing canvas/rAF setup: full control over bounce feel, guaranteed landing in the paid bucket, zero dependencies.

## Changes

### 1. New `apps/web/lib/plinkoPhysics.ts` — steered physics sim
- World per row-count (reuses current geometry: `gapX = W/(rows+2)`, `gapY = (BOTTOM-TOP)/(rows+1)`, peg rows 2..N), side walls, bucket divider pins below the last row.
- Ball state: position, velocity, spin; gravity ≈ 1800 px/s², restitution ≈ 0.55, tangential friction; spawns above the top peg with slight x-jitter. Target drop duration ~1.2–1.8s (matches current pacing).
- Fixed-timestep integration (120 Hz accumulator) driven from the existing rAF loop.
- Peg hit = circle-circle impulse resolve, then **steering**: post-collision horizontal velocity is biased to the server's `path[row]` side, plus a gentle drift toward the target column while falling — real-looking bounces that still guarantee the paid bucket. Final row dividers make the landing exact.
- Balls don't collide with each other (industry standard — keeps steering reliable with many balls).
- O(balls × 3) collision checks via row-based spatial lookup; callbacks `onPegHit(row)` / `onLand(bucket)`.

### 2. Rewrite animation layer in `apps/web/components/PlinkoScreen.tsx`
- **Remove the `dropBusy` single-flight lock entirely**: no button/rows/risk/bet disabling during flight, each drop is an independent `play.mutate`, unlimited concurrent balls (balls live ~2s so count self-caps; silent cap ~80 active for perf).
- Each ball snapshots its own rows-geometry + risk table at drop time. Changing **risk** mid-flight is safe (balls keep flying, flash from their own table); changing **rows** fades in-flight balls out quickly (bets already settled, result chips persist).
- **Visible, juicy balls**: radius ~7.5, radial gradient + glow, motion trail (last ~8 positions), velocity-based squash & stretch, visible release from above the top peg.
- **Juice**: peg-hit flash ring + peg pulse, bucket squash-bounce on land, small particle burst, floating `+mult×` popup.
- Sounds (existing `lib/sound.ts`): `winTick(row)` per peg hit (pitched, throttled when many balls drop at once), `chipClink` on land, `bigWin` ≥10×, `jackpot` >1×.
- Result banner + history chips now update on the physics land event instead of a 1400 ms timer.

### 3. `services/backend/internal/httpapi/handlers_play.go` — one line
- Raise the play rate limit from 20 → 60 requests / 10 s / user so rapid multi-dropping doesn't hit 429s (the limiter is generic across instant games; other games stay single-flight client-side anyway).
