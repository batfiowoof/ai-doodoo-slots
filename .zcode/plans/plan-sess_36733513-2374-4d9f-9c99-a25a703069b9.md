# Social Layer: Chat, Leaderboard, Emotes + Interactivity

## Architecture summary

One new **SocialDock** component mounted globally in `app/layout.tsx` (fixed-position, portal overlays) gives every screen — lobby and all game rooms — chat, the emote wheel, online roster, leaderboard, big-win banners and rain animations over a single lobby-mode WebSocket. Backend adds a `SocialHandler` on the gameserver hub (new WS message types), a `00014_social` migration + sqlc queries, leaderboard/player REST endpoints on the shared `httpapi` server, and a big-win publisher in the settlement paths. All money movement (tips, rain) goes through the existing wallets/transactions ledger inside store transactions.

## Backend (services/backend)

**1. Migration `db/migrations/00014_social.sql`** (goose, Up/Down):
- `chat_messages(id BIGSERIAL PK, user_id BIGINT REFERENCES users, kind TEXT CHECK IN ('chat','system'), body TEXT CHECK length<=256, deleted BOOLEAN DEFAULT false, created_at)` + index on `created_at DESC`.
- `chat_mutes(user_id PK REFERENCES users, muted_until TIMESTAMPTZ, reason TEXT, muted_by BIGINT, created_at)`.

**2. sqlc queries** (`db/queries/chat.sql`, `leaderboard.sql`, then `sqlc generate`):
- Chat: insert message, list recent 50 (join users, exclude deleted), soft-delete, upsert/get/delete mute.
- Leaderboard: per metric (`biggest_win` = MAX(payout−bet), `net_profit` = SUM(payout−bet), `wagered` = SUM(bet)) grouped by user, window filter `created_at >= now() - $1::interval` (NULL = all-time), join users, exclude non-active users; plus a "my rank" COUNT query per metric/window.
- Player card: profile + biggest-win aggregate by user id.

**3. WS social handler** — new `internal/social` package implementing a `SocialHandler` interface (new, in `internal/ws/ws.go`, injected via `Hub.SetSocialHandler` from `cmd/gameserver/main.go`, same pattern as BetHandler). In `client.go`: extend `inboundTypes` + `handle()` with:
- `send_chat {body}` → handler: status check, active-mute check (error `muted`), 500ms per-connection cooldown (`chat_cooldown`), persist, return → hub `BroadcastAll("chat_message", …)`.
- `send_emote {emoteId}` → validate against a small Go emote-id set, 400ms cooldown, ephemeral `BroadcastAll("emote", …)`.
- `send_tip {toUserId, credits}` → ledger transfer (debit/credit + `transactions` kind `tip`, min 1 / insufficient-funds checks) → broadcast `tip` + system chat line.
- `make_it_rain {credits}` → hub roster of online users (dedup by UserID, active) → split evenly inside one store tx → broadcast `rain` + system chat line + `chat_message`s.
- `chat_delete {messageId}` / `chat_mute {userId, minutes, reason}` → gated on `Identity.IsStaff()`, persist, broadcast `chat_deleted` / error to target.
- Errors reuses the existing `{type:"error", payload:{code}}` shape.

**4. Big-win announcements** — new bus topic `wins`. In `internal/play/service.go` (instant settle) and `internal/round/runner.go` settle path: when `payout >= bet * 15` (env `BIG_WIN_MULTIPLIER`, default 15), publish `{user, gameId, bet, payout, multiplier}`. Hub subscribes in `Run()`, broadcasts `big_win` to everyone and inserts a `system` chat message row (so it replays in history).

**5. Presence roster** — extend `Hub.presence()`/lobby_summary payload with per-scope rosters: `[{userId, displayName, avatarPreset, avatarVersion, role}]` for lobby + each active room (feeds the Online-now popover).

**6. REST + contract** — in `internal/httpapi` (served by api and gameserver): `GET /chat/messages?limit=50`, `GET /leaderboard?metric&window` (entries + `me`), `GET /players/{id}`. Update `openapi.yaml`, regenerate `apps/web` types (openapi-typescript).

## Frontend (apps/web)

**1. `lib/useCasinoSocket.ts`** — shared connect/reconnect/generation-guard hook (modeled on `useLobby.ts`, always `subscribe_lobby`); returns `{status, send, lastMessage}`. Existing room components untouched.

**2. `lib/emotes.ts`** — registry: `{id, label, emoji}` for ~12 v1 emotes (emoji placeholder chips) with optional `src` field; user later drops GIFs into `public/emotes/` and sets `src` — wheel, chat inline rendering and float overlay all read from this one registry. Chat renders `:emoteId:` tokens inline.

**3. `components/SocialDock.tsx`** (mounted in `app/layout.tsx`, round-chip cluster bottom-right to match the wheel satellites): CHAT (unread badge), EMOTE, ONLINE (count), TOP chips.
- **Chat panel**: side panel with retro neon chrome — Avatar + role-colored names (staff gold), system lines centered cyan, input + send, staff right-click menu (DELETE / MUTE 10m / 1h), own-name mention highlight + alert sound.
- **Emote wheel**: radial mini-wheel of 8–12 chips popping from the EMOTE chip; sends `send_emote`, floats locally instantly.
- **Floating emote overlay**: body portal, `pointer-events:none` — emotes spawn bottom-right, wobble-float up ~60vh and fade (new `emoteFloat` keyframes).
- **Online roster** popover from lobby_summary roster.
- **Leaderboard dialog**: NeonDialog, metric tabs (BIGGEST WIN / NET PROFIT / WAGERED) × window tabs (TODAY / WEEK / ALL-TIME), top-3 podium with glowing avatars, rows 4–20, own-rank footer, 30s refetch.
- **Player card**: clicking any username (chat/roster/leaderboard) → card with avatar, role, member-since, biggest win + TIP presets (50/100/500/custom).
- **Big-win banner**: `big_win` → top-center gold banner (`bannerIn` family) + `sound.bigWin`.
- **Rain animation**: `rain` → coin-storm of ~24 `coinFly`-style coins across the viewport + jackpot sound.
- **Sounds** (`lib/sound.ts`): new `chatPop`, `emotePop` (throttled for others' messages), `muteTromenoop` not needed — reuse `error`/`turnAlert`.

**4. `globals.css`**: new keyframes — `emoteFloat`, `coinRain`, `winBanner`, podium glow.
