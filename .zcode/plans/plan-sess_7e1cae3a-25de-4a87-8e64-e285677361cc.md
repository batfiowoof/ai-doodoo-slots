# Personalized Lobby — Netflix-style Recommendation Engine + RG Layer

## Goal
Per-player lobby: personalized ordering, a "FOR YOU" drill-down ring (continue / recommended / trending / new), badge chips with honest "because you played…" labels — engineered so RG rules gate all promotional content. Bets+launch events feed a deterministic scorer; a prefs toggle and self-exclusion UI ship in AccountModal.

**Non-goals this round:** ML/collaborative filtering (catalog is ~10 games — tag similarity is more honest), geo-IP, admin "preview as user" tool. Follow-ups at most.

---

## 1. Database — `services/backend/db/migrations/00015_personalization.sql` (goose)

1. **`game_metadata`** — `game_id TEXT PK, category TEXT ('slots'|'instant'|'table'|'live'), collection TEXT, tags TEXT[], is_new_until TIMESTAMPTZ NULL, blurb TEXT NULL`. Seeded for all ~10 game ids (read exact ids from `Registry.Listings()` + rooms seed migrations: 3 slots, dice, plinko, mines, blackjack, crash, roulette, holdem).
2. **`player_events`** — `id BIGSERIAL PK, user_id UUID NOT NULL, session_id UUID NULL, event_type TEXT NOT NULL, game_id TEXT NOT NULL, created_at TIMESTAMPTZ DEFAULT now(), context JSONB NULL`; indexes `(user_id, created_at DESC)` and `(event_type, game_id, created_at DESC)`. Guests are user rows, so this covers browsers-who-never-bet.
3. **`user_prefs`** — `user_id UUID PK, personalize_enabled BOOLEAN NOT NULL DEFAULT true, updated_at TIMESTAMPTZ`.

Queries in `db/queries/personalization.sql` (sqlc, leaderboard.sql as template): game metadata list, insert events (batch), per-user per-game aggregates (count/last-played/net, trailing windows), global trending (launches+bets last 24h), prefs get/upsert. Regenerate sqlc.

Note: only the **api** process touches these tables → no gameserver migration-boot race.

## 2. API — Go (`internal/httpapi`, stdlib mux pattern)

- **Enrich `GET /api/v1/games`**: join `game_metadata`; `Game` schema gains `category, collection, tags, isNew, blurb`.
- **`POST /api/v1/events`** (`handlers_personalization.go`): `{events: [{type:"launch", gameId, context?}]}`, whitelist types, ≤20/batch, fire-and-forget insert, 202. Auth = existing `currentUser` (guests fine).
- **`PATCH /api/v1/me/preferences`**: `{personalizeEnabled}` — follows the profile mutation pattern (sqlc → re-read → audit_log `prefs.update`).
- **`GET /api/v1/lobby/personalized`** — new `internal/recs` package, on-demand SQL + 30s per-user in-memory cache (map+mutex; no Redis). Payload:
  ```
  { personalized, promoEligible, reason,
    gameRank: [gameId…],                    // full ranked order, all games
    sections: { continue[], forYou[], trending[], new[] },   // entries {gameId, why?/label?}
    badges: {gameId: "HOT"|"NEW"|"RECENT"|"TOP PICK"}, why: {gameId: "BECAUSE YOU PLAYED …"} }
  ```
- **Scorer** (`internal/recs/scorer.go`, injected clock, table-driven unit tests): weighted blend — recency-weighted play affinity (~50%), time-decay recency (~20%), 24h trending (~20%), new boost (~10%). `forYou` seeds = top category-tag neighbors of most-played game ("because you played X" via tag overlap). `typeRank`/group ordering derived client-side from `gameRank`.

### RG gate (runs before scoring; sets flags + reason)
| Condition | Effect |
|---|---|
| `users.status != 'active'` (banned/self-excluded) | `personalized=false, promoEligible=false`, reason `account_restricted` |
| `user_prefs.personalize_enabled=false` | `personalized=false, promoEligible=false`, reason `toggle_off` — lobby renders exactly as today |
| Cold start (<5 bets across <2 games) | neutral order, but continue/trending still shown, reason `cold` |
| **Risk suppression**: trailing-24h net loss beyond threshold AND stake escalation (avg bet 1h > 1.5× 7d avg; constants env-overridable) | `promoEligible=false`, reason `risk_suppressed` — strips new/trending/forYou promo seeds + HOT/NEW badges; keeps CONTINUE + neutral ordering (navigation aid, not a push) |

**Copy rules (enforced in code, not vibes):** descriptive labels only ("BECAUSE YOU PLAYED…", "YOUR RECENTS", "EVERYONE'S PLAYING"); never urgency, countdowns, "win it back", loss-framing, or deposit prompts inside personalized content; suppression surfaced as a small neutral "SAFER PLAY · PROMOS PAUSED" chip — no shaming.

## 4. Lobby UI (`apps/web/app/page.tsx`) — all recommendations chosen: FOR YOU node + ordering

- Order groups by best-ranked member (`gameRank`); slots children and table leaves by `gameRank`. Static order stays the fallback for cold/toggle-off.
- **FOR YOU root node** (first seat, gold sparkle accent, animated, existing sounds only) drilling into a personalized ring built from `sections` — children reuse `gameNode`/`roomNode` art, `RadialNode.badge` corner chips = `badges` map, `status` line = `why` / relative time ("2H AGO"). Hub face while drilled: "PICKED FOR YOU ◀ BACK". Ellipse auto-sizes (RadialMenu already handles n>8).
- Suppressed mode: FOR YOU ring shrinks to CONTINUE-only, promo badges stripped, neutral chip added. Toggle-off: current lobby, untouched.
- stageScale constant untouched — everything lives inside the wheel.
